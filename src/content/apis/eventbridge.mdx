## Problem and constraints

Consumers kept missing webhooks. When a delivery failed, the event was gone, and the only way to recover was digging through logs. The product decision: expose delivery as an API where every event is stored, every attempt is recorded, and any event can be replayed on demand.

## Key decisions

- Model events as a first-class resource: `POST /events` to publish, `GET /events/{id}` to inspect, `POST /events/{id}/replay` to re-deliver.
- Use an outbox table so no event is lost before its first delivery attempt.
- Authenticate every call with an API key in the `X-API-Key` header, scoped per consumer.

## The hard part

Replay semantics. A consumer needed to replay a single event without re-delivering the whole batch. The fix: per-event delivery records with their own retry state, so replay targets exactly one event.

## Results and lessons

End-to-end delivery sits under 5 seconds at p95, and every attempt is visible in the API. Consumers stopped asking "did we get the event?" and started asking "what happened to this one?" The full OpenAPI spec lives in Swagger; the endpoints above are the ones I reach for daily.
